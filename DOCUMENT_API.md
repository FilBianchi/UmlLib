# Editable documents and structured validation

Both UML backends provide this public contract, without Qt dependencies:

```python
from umltools.xmi import XmiDocument, load

doc = XmiDocument.new('Shop', semantic_version='2.4.1')
model = doc.roots[0]
domain = doc.create('Package', owner=model, feature='packagedElement', name='Domain')
customer = doc.create('Class', owner=domain, feature='packagedElement', name='Customer')
attribute = doc.create('Property', owner=customer, feature='ownedAttribute', name='name')
string = doc.create('PrimitiveType', owner=model, feature='packagedElement', name='String')
doc.set_value(attribute, 'type', string)
identity = doc.identity(attribute)
doc.detach(attribute)  # retained as a live root
doc.move(attribute, owner=customer, feature='ownedAttribute')
assert doc.resolve(identity) is attribute
doc.save('shop.xmi')
assert load('shop.xmi', semantic_version='auto').semantic_version == '2.4.1'
```

`classifiers()`, `containment_features(owner)` and `compatible_classes(owner, feature)`
support metamodel-driven editors. Abstract/incompatible classes, read-only/derived
assignments, foreign-session owners and supplied core references are rejected.
Raw setters keep their existing cross-session contract. Minimum multiplicities can
remain incomplete while constructing models and are checked by validation.

Creation and movement roll back touched links, including supplied preexisting
composite objects. These guarantees are per operation, not a batch transaction or
undo/redo. Applications must serialize access to a document; concurrent editing is
not supported. `delete(element, cascade=True, on_references='detach')` uses the
selected backend's logical deletion. Deleted IDs cannot be resolved, even after
direct legacy deletion.

`synchronize()` discovers direct construction inside `with doc.session:`, removes
tombstones and reconciles roots/identities. Export, `identity()` and detailed document
validation synchronize automatically. Existing root fields are snapshots until then.

Export policies:

- `doc.dumps()` / `doc.save(path)` and generic `dumps(doc)` / `dump(doc, path)` use
  **document** scope: all live roots across loaded resources, including detached
  objects and unreferenced dependency roots. This extends the old primary-root policy.
- `doc.dumps(scope='reachable', roots=[model])` explicitly selects a graph closure.
  The existing `dumps(model)` and `dumps([model])` still follow those roots.
- `bundle` and external-reference maps keep their existing contracts. Bundled ID
  clashes may be renamed. In-memory identities stay stable; source URI provenance
  is not preserved as a round-trip identity map. Opaque vendor reference encodings
  are not rewritten. This is known-graph exchange, not byte-for-byte preservation.

Saving serializes first, writes and flushes a temporary file in the destination
directory, then atomically replaces the target. Failures preserve the original file.

## Validation

```python
report = doc.validation_report()
for issue in report.issues:
    print(issue.status, issue.rule, issue.uri, issue.element_id,
          issue.feature, issue.path, issue.message, issue.cause)
json_data = report.to_dict()
element_report = customer.validate_detailed(recursive=True)
```

Issues carry the object for navigation and JSON-safe locations. Native exception
messages are retained where available; legacy/profile/supplementary validators may
only supply rule/category. Document validation checks every live core object and
runtime profile value once, including objects not contained by another element.

Reports separate `violations`, `evaluation_errors`, `unsupported` and `warnings`.
Cross-session references are incomplete-context warnings, not UML violations.
`is_valid` is False for known violations, None for incomplete coverage/evaluation or
decoding without known violations, and True for a complete result of available
checks. It never certifies full UML conformance.

The packaged `validation-obligations.json` is regenerated by `semantic_report.py`.
It exposes known partial 2.5.1 requirements by applicable metaclass, including
ProtocolConformance and trace/prose obligations. This is conservative and does not
infer whether a specific instance exercises every omitted case; it is not a complete
normative requirement census. 2.4.1 retains its unaudited-prose marker. The legacy
`validate()` tuple format is unchanged and does not include the additional census.
